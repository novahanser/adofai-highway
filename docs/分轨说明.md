# 4K／6K／8K 分轨说明

本分支基于 [seenws/adofai-highway](https://github.com/seenws/adofai-highway)，将游戏内的单轨提示扩展为可选的 4K、6K、8K。分组思路参考 [helloLZR/Adofai-Macro](https://github.com/helloLZR/Adofai-Macro/tree/c6f2d20e2b508285709eb90d2e6de78bf4845d20) 的内轮、主手、单指速度和小角多押规则，并重新实现为直接面向目标轨道数的分配器。

## 使用

1. 将安装包内文件解压到游戏 `Mods/AdofaiHighway` 目录，替换 DLL 和 Info.json，然后重启游戏。已有 `Settings.xml` 会保留。
2. 打开 `Ctrl+F10`，启用 `ADOFAI Note Highway - Multi-lane`，点击该行的设置图标。
3. 在“分轨 / Lanes”页选择 1K、4K、6K 或 8K。菜单修改立即刷新当前谱面的分轨，不需要重新加载关卡。
4. 使用 UMM 的 Save 保存设置。已有用户设置缺少新增字段时使用默认值，默认轨道数为单轨。

左半区为左手，右半区为右手，轨道号从左向右递增。插件提供手法提示，不锁定实体键位，也不会替玩家输出按键。可以自行选择每轨对应的键；游戏本身仍按其原有规则接收输入。

## 设置

| 设置 | 作用 |
| --- | --- |
| 内轮 | 根据时间密度分组，组内由外侧手指向内侧依次分配；轨道用完后轮换到另一手 |
| 左右交替 | 按输入顺序交替左右手，适合希望持续分散按键的场景 |
| 主手 | 内轮稀疏段优先使用该手；交替模式从该手开始 |
| 单指 KPS | 内轮分组窗口为 `1/(2×KPS)` 秒；默认 7.3。这是手法参数，不是对每轨连打速度的硬上限 |
| 跟随播放倍速 | 用歌曲 pitch 换算实际时间密度后决定手法；不修改游戏时间 |
| 小角多押视觉对齐 | 可选把近邻音符画在同一高度，默认关闭；真实击打时刻和游戏判定不改变 |
| 整个轨道区宽度 | 所有轨道共享的总宽度，增加轨道数不会乘倍扩大覆盖区域 |
| 轨道间距／分隔线／编号 | 调节各列的可读性 |
| 左右手颜色／多押颜色 | 普通音符可按手着色，多押使用独立颜色 |
| 下落流速 | 10–10000 px/s，支持对数滑条和数值输入 |
| 音符厚度 | 2–80 px，同时影响普通音符、多押条与长按头尾 |
| 判定线位置 | 可选距底部 0–4320 px，或按轨道区顶部 0–100% 定位；最终限制在可见轨道区域内 |
| 判定线厚度 | 1–20 px |
| 菜单语言 | 简体中文或 English，可即时切换并保存 |
| 手动偏移 | 正值让音符更晚到达判定线，负值更早；以游戏输入时钟为基准 |

“布局 / Layout”页还保留高度、背景透明度、节拍与小节线；“颜色与同步 / Color & Sync”页显示游戏输入与视觉时钟之间的校准差值。旧版从玩家落点学习偏移的方法已改为直接使用游戏输入时钟，避免把玩家早按／晚按误差累积为显示漂移。

## 时间和事件

插件直接读取游戏已经计算好的 `entryTime`，使用游戏 conductor 的歌曲时钟。旋转、变速、暂停、多星和歌曲偏移等时间计算交给游戏。分轨不会再次用 Python 解析器重新计算时间，因此不会继承此前分析到的 AutoPlay／Hold 索引缺陷。

- 起点、装饰、自动段、自由移动段不生成手动按键提示。
- 中旋由游戏自动处理，只保留后继实际输入，不多画一次按键。
- 长按从长按头到下一个有效节点，以该轨的长条显示；普通尾端只需释放，不重复生成点击。
- 连续长按仍保留新长按头。多押长按显示同拍多轨长条。
- 真实多押按游戏的 `tapsNeeded` 展开；游戏开启多押“Hit Once”时，相应提示也降为一次输入。
- 长按尾端遇到 N 次多押时，释放已提供一次输入，另显示 N−1 次需求。
- 自动长按的普通或多押尾端由游戏自动完成，不再生成手动输入；其后下一枚普通手动音符仍然保留。
- 暂停、重新开始和检查点使用当前游戏时钟；编辑器重新计算谱面时间后会重建提示，即使它复用原来的轨道列表。

## 目标轨道数与容量

分配器直接使用 N 个独立轨道，不把一份 32 键宏按键表取模折叠成 N 列。同拍音符分配到不同轨道，长按在释放前占用自己的轨道。

如果需求确实超过目标轨道容量，显示红色 `+N key(s): lane capacity exceeded` 提示；不会静默丢掉需求、截断已有长按或假装把两个同时输入放到同一轨。此时可切换到更多轨道，或关闭可选的近邻视觉合并。

分轨是确定性的启发式提示，不保证生成符合所有传统键盘音游制谱习惯的谱面。它不会改变 ADOFAI 的判定系统，也不导出 `.osu` 或其他游戏的谱面文件。

## 近邻视觉多押

使用相邻间隔 `<50 ms`、后一个音符的来向转角小于等于 15°（有效 BPM 至少 300 时为 30°），以及整段跨度不超过 100 ms 的规则。超过 100 ms 的整段不合并，不切成多个假想和弦。真正同刻的输入始终按同刻组处理。

视觉合并只改变显示时间，按下时间、释放时间始终保留。不要把画面上的对齐理解为游戏将原来略有先后的击打改为严格同时。

## 构建与测试

需要 .NET SDK 6 或更新版本、本机 ADOFAI 和已安装的 UnityModManager。

```powershell
./scripts/build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\A Dance of Fire and Ice'
```

脚本依次运行纯算法、设置 XML 迁移、游戏事件转换和布局边界测试，构建 .NET Framework 4.8 插件，生成 `dist/AdofaiHighway-0.7.1-multilane.zip` 与 SHA256。安装包只有插件、信息文件和说明，不包含游戏或 Unity 的 DLL。

四个控制台测试项目不需要游戏 DLL，也不启动游戏。完整插件构建才引用本地游戏程序集；游戏画面和实际输入兼容性应另行实测。
